# Cabinet of War — working notes for Claude

Solo historical strategy game (Habsburg monarchy, October 1740) in a 3D browser world. The player gives orders; an AI chat (Claude, by copy and paste — no API) adjudicates each turn. Plays at https://nathanpljohnson.github.io/cabinet-of-war/.

## Where things live
| What | File |
| --- | --- |
| What Claude is told every turn (rules, world, fortune, endings) | `w3d/contract.md` |
| Packet, reply format, merge rules, reply checks, fortune | `w3d/turn.js` (pure, tested) |
| Page glue: review dialog, saves, campaign file, book log, urgent choices, trust, enemy temper | `w3d/campaign.js` |
| Continuity checks (dead men writing, canon, standing) | `w3d/continuity.js` |
| Letters, dispatch, notebook, book of the campaign | `w3d/shell.js` |
| 3D place: people, scene tags, whereabouts groups, winter quarters / campaigning | `w3d/region.js` |
| Table battle and the ride over the field afterwards (`setAftermath`) | `w3d/battle3d.js` |
| Views, weather, precipitation, day/night, boot | `w3d/main.js` |
| Almanac (47 plots, systems, stakes, calendar, verification) | `w3d/almanac.json` — generated by the build from `src/state.json` |
| Opening letters, cast, canon, chronicle | `src/opening.json` |
| Orders section of the packet (desk engine) | `src/case.js` |
| Test replies | `w3d/mocks/*.json` (`__w3d.mockReply('living')` in the console) |

`cabinet-of-war.html` is generated. Never edit it by hand.

## Build, run, test
```bash
python3 src/pdx_build.py && python3 src/w3d_build.py   # rebuild the page (always both, in this order)
python3 w3d/dev_server.py 8000                          # play at http://localhost:8000/
python3 -m pytest -q tests                              # reply format, merge rules, packet, build
```
`w3d/` modules load directly; only `src/` changes need a rebuild.

## The turn loop
Seal → packet (contract + orders + fortune + active almanac plots + the record's seal + live state) → Claude → reply `{kind:"turn", schemaVersion:3, seal, changes:{…}}` with only what changed → `checkReply` (errors, fixes, warnings; a wrong seal is refused) → `mergeTurn` → `checkContinuity` → accept → the record's next link (`state.record.chain`) + book entry + campaign file download.
Every ten turns the packet asks for a chronicle volume (`hidden.volumes`, append-only).
Merge rules are in `turn.js` (`BY_ID`, `APPEND`, per-turn fields). Change the rules there and in `replyFormat()` together, then run the tests.

## Rules that must hold
- Lighting: no scene may go near-black. After any lighting or weather change run `await __w3d.lightCheck()` in the console; every row must pass `LIGHT_FLOOR` (`w3d/main.js`).
- The player sees no meters, scores or numbers about people; standing shows only in behaviour and letters.
- Orders only, no conversations. In-world presentation; dark glass + paper letters; Baskerville / Iowan.
- Never decide outcomes in code. Code supplies vocabulary (weather kinds, scene tags, tempers) and checks; Claude chooses.
- Test in a separate browser profile or a fresh port so the player's own save is not touched. Turn off the per-turn download first: `localStorage.setItem('cabinet-of-war:w3d-autosave','false')`.

## Saves
Browser storage (`cabinet-of-war:*` keys) plus a campaign file (Notebook → The record) holding the state and every local key, with a fingerprint over both. Snapshots are pruned to the last two or three turns. Ironman (`state.record.ironman`, one-way) refuses altered files, files older than the browser's high-water mark (`w3d-highwater`) and whole saved states. The fingerprint shows tampering; it is not cryptographic.
