# Cabinet of War — working notes for Claude

Solo historical strategy game (Habsburg monarchy, October 1740) in a 3D browser world. The player gives orders; an AI chat (Claude, by copy and paste — no API) adjudicates each turn. Plays at https://nathanpljohnson.github.io/cabinet-of-war/.

## Build, run, test
```bash
python3 src/pdx_build.py && python3 src/w3d_build.py   # rebuild the page (always both, in this order)
python3 w3d/dev_server.py 8000                          # play at http://localhost:8000/
python3 -m pytest -q tests                              # reply format, merge rules, packet, build, grounds
python3 src/ground_build.py [id …]                      # rebuild battle grounds (network; pip install tifffile imagecodecs fsspec aiohttp pyarrow)
```
A new library ground needs an entry in `GROUNDS` in `src/ground_build.py`, its id in `GROUNDS` in `w3d/turn.js`, and a line in the contract's "Battle grounds" (the tests check the first two agree). Look at `src/.ground_cache/<id>.png` before using it: modern reservoirs, harbours and spoil heaps must be removed by hand (`drop_water`). `__w3d.ground('prague')` or `__w3d.ground({kind:'marsh'}, [lat, lon])` puts a ground on the table in the console.
`w3d/` modules load directly; only `src/` changes need a rebuild.
The `.glb` files in `w3d/assets` hold only the clips the game plays (`src/slim_glb.py`, list in `KEEP`). To use another clip, restore the full file from git (`git show 6447ec8:w3d/assets/<file> > w3d/assets/<file>`), add the name to `KEEP`, and re-run the script.

## The turn loop
Each packet stands alone; the player starts a fresh chat each turn. The packet sends cast, locations and fortresses as pipe tables (`TABLES` in `turn.js`), not JSON. With "My Claude Project holds the rules" (Notebook → The record) the packet leaves out the contract, the reply format and the almanac's systems and names the rules version (`rulesVersion`); the player adds `rulesText()` to the project once per version.
Seal → packet (contract + orders + fortune + active almanac plots + the record's seal + live state) → Claude → reply `{kind:"turn", schemaVersion:3, seal, changes:{…}}` with only what changed → `checkReply` (errors, fixes, warnings; a wrong seal is refused) → `mergeTurn` → `checkContinuity` → accept → the record's next link (`state.record.chain`) + book entry + campaign file download.
**The courier through the repository** (the default; Notebook → The record → How the courier rides): sealing copies an errand for a coding agent (Claude Code or Codex) working in this repository. The errand (`courierErrand` in `turn.js`) works from any folder: the agent takes a sparse clone of only the files it needs, reads the rules with `node tools/turn-tool.mjs rules` (battle rules only with `--battle`, which the errand asks for when `isBattleNear`), writes the reply to `turns/<campaignId>/turn-NNN.json` carrying the dispatch's id, saves only the packet's last line (the check block: `checkSkeleton`, ~3.6 KB) and checks the reply with `node tools/turn-tool.mjs check <check block> <turn file>` (the same `checkReply` + continuity the page runs; tested to give the same verdict as the whole state), and pushes that one file to main. Keep what crosses the exchange small: the agent should never have to re-type the packet. The page polls for the next turn's file every 30 s after a seal (and on load), and applies it at once if it passes every check; otherwise it shows the review. A reply answering an earlier sealing of the same turn (`dispatch` mismatch) is refused. If you are such an agent, adjudicating a turn: write only the turn file, never game code — unless the player's note on the game (the dispatch's out-of-character box, `notesOnGame` in `turn.js`) asks for a change; then, after the turn is pushed, make the smallest change that does it, keep to these rules, run the tests and push it (the errand's step 6).
Every ten turns the packet asks for a chronicle volume (`hidden.volumes`, append-only).
Merge rules are in `turn.js` (`BY_ID`, `APPEND`, per-turn fields). Change the rules there and in `replyFormat()` together, then run the tests.

## Rules that must hold
- Lighting: no scene may go near-black. After any lighting or weather change run `await __w3d.lightCheck()` in the console; every row must pass `LIGHT_FLOOR` (`w3d/main.js`). It covers every weather; check each season too (`__w3d.look({ season })` first).
- The player sees no meters, scores or numbers about people; standing shows only in behaviour and letters.
- Orders only, no conversations. In-world presentation; dark glass + paper letters; Baskerville / Iowan.
- Never decide outcomes in code. Code supplies vocabulary (weather kinds, sights, tempers) and checks; Claude chooses.
- Test in a separate browser profile or a fresh port so the player's own save is not touched. Turn off the per-turn download first: `localStorage.setItem('cabinet-of-war:w3d-autosave','false')`.

## Saves
Browser storage (`cabinet-of-war:*` keys) plus a campaign file (Notebook → The record) holding the state and every local key, with a fingerprint over both. Snapshots are pruned to the last two or three turns. Ironman (`state.record.ironman`, one-way) refuses altered files, files older than the browser's high-water mark (`w3d-highwater`) and whole saved states. The fingerprint shows tampering; it is not cryptographic.
